# 第一章 导论：从 MA20 择时到组合管理

> 本手册基于一个真实运行的个人投资工作台（Streamlit + SQLite + CSV）写成。书中所有代码引用、参数表、回测数字均来自当前仓库与本地缓存的真实数据，复现脚本见 `docs/handbook/repro_hb_backtest.py`，输出见 `output/handbook_backtest_results.json`。

## 1.1 这本手册讲什么

本手册不是一本泛泛的"量化入门"，而是把一个**正在实盘运行的系统**拆开给你看：它如何取数、如何保证数据不被污染、如何计算 MA20 信号、如何回测、如何把回测落到每天的实盘操作提醒、以及如何把 ETF 实盘与期货实盘的账算清楚。

全书围绕四个主题：

1. **数据工程**（第 3–8 章）：缓存体系、交易日历、多源容错、只追加（append-only）历史、盘中价与正式收盘价的隔离、复权处理。
2. **择时引擎**（第 9–13 章）：MA 带状择时的理论与数学、指数 MA20 报告、ETF 逐只参数表、512890"停车 ETF"聚合逻辑、多级实时刷新调度。
3. **回测体系**（第 14–20 章）：单标的 MA 回测、组合择时与半仓袖套、指标体系、动量轮动、年度动态组合、严格组合审计、动态阈值两阶段研究。
4. **组合与实盘**（第 21–28 章）：50 万元模拟策略、ETF 实盘记录、期货实盘双口径盈亏、风险管理、自动化运维、缺陷清单与研究议程。

## 1.3 设计哲学：五条铁律

通读全部代码后，可以提炼出贯穿始终的五条工程铁律，它们也是本手册反复出现的主题：

1. **缓存优先（cache-first）**。每个页面先读本地缓存再谈联网。`任务与数据` 页的手动更新甚至要求"先展示只读预览，再二次确认才联网"。
2. **只追加（append-only）**。一旦某个日期的行情被缓存，后续刷新不得改写该行。修正走独立叠加层（`index_source_correction_history`），而不是原地覆盖。
3. **盘中价与正式日线物理隔离**。盘中/午间报价只存在于进程内存（`_RUNTIME_QUOTE_CACHE`）与会话状态，永不写入日线缓存；正式日线只在"收盘后 10 分钟"（settlement delay）后才允许落库。
4. **回测与实盘严格分离**。模拟回测（`策略回测`、50 万模拟）绝不写入实盘台账（`live_trades`）；`实盘记录` 与 `期货实盘` 是两套独立的表。
5. **可解释优先于自动化**。所有自动对账（期货手工成交接管、同花顺日盈亏核对）在歧义时标记"待核对"让人工裁决，而不是替人做决定。

还有一个容易忽视的全局约定：**UI 语言为中文**，所有用户可见的标签、表头、错误信息都是中文；**颜色遵循 A 股习惯——红涨绿跌**（如 `components/position/cards_tables.py` 中涨用 `rgb(190,18,60)`，跌用 `rgb(22,101,52)`）。

## 1.4 运行环境的一个重要事实

`core/cache.py` 的文件锁基于 `fcntl`（第 14-17 行以 `try/except ImportError` 守卫：Windows 下退化为"无跨进程锁的占位实现"，注释明确说明这是为单进程 Streamlit 部署做的取舍——这一守卫是写作本手册期间刚进入工作区的未提交修改），而 `core/paths.py` 在 Windows 上把运行时目录指到 `~/investment_dashboard_data`，`scripts/update_index_ma20_scheduled.py`、`monitor_iron_ore_price.py`、`monitor_position_timing_trades.py` 三个脚本仍**直接顶层 `import fcntl`**。这意味着：

- **项目本体设计运行于 WSL/Linux**：`.venv` 是 Linux Python 3.12 虚拟环境；守护脚本在 Windows 原生 Python 下仍然 `ModuleNotFoundError`；
- 页面侧（`core.cache`）在加了守卫后已可在原生 Windows 单进程运行，但跨进程并发安全仅 WSL 有；
- Windows 侧的计划任务通过 `wsl.exe -d Ubuntu -- ...` 桥接调用（见 `scripts/run_position_timing_trade_alert_task.ps1`）——**Windows 是闹钟，WSL 是引擎**。

写作本手册时，真实回测就是用 WSL 中该项目的 `.venv/bin/python`（Python 3.12.3 / pandas 3.0.5）在本地缓存（截至 2026-09-02 的 14 只 ETF 前加复权日线、截至 2026-08-14 的指数收盘确认历史）上重放得到的。

## 理论

个人投资者做量化的核心难题不是"找一个神奇指标"，而是**流程的可靠性**：数据会不会错、信号会不会漂移、回测会不会自欺、实盘能不能照做。本项目的回答是把学术界的做法工程化：

- 用**状态依赖的阈值带**（MA ± x%）抑制 whipsaw（锯齿震荡），这是移动平均择时文献（Brock, Lakonishok & LeBaron 1992；Zakamulin 2017 等）中标准的改进手段；
- 用**冻结参数 + 真正样本外跟踪**（`portfolio_audit_tracking.py`）对抗回测过拟合；
- 用**多源交叉复核**（独立源 ±0.20% 容差）替代对单一数据源的信任；
- 用**半仓持有/半仓择时**（half timing）在"怕踏空"与"怕回撤"之间取折中，这与趋势跟随文献中"always-in 的一半 + timing 的一半"等价于把策略暴露写成 `0.5 + 0.5·signal`。

## 数学原理

设价格序列 $P_t$，MA 信号的最一般形式为仓位函数：

$$w_t = f\left(\frac{P_t - MA_n(P)_t}{MA_n(P)_t}\right), \qquad MA_n(P)_t = \frac{1}{n}\sum_{i=0}^{n-1} P_{t-i}$$

其中带阈值的滞回（hysteresis）实现为：

$$w_t=\begin{cases}1, & P_t > MA_n \cdot (1+\theta)\\ 0, & P_t < MA_n \cdot (1-\theta)\\ w_{t-1}, & \text{否则}\end{cases}$$

策略净值 $V_t = V_{t-1}\cdot(1 + w_t r_t) - \text{费用}$，其中 $r_t = P_t/P_{t-1}-1$。半仓策略即 $w_t^{half} = 0.5 + 0.5 w_t$。这些公式在第 9、11、14 章会逐一对应到代码行。

## 代码分析

`app.py` 值得注意的三个细节：

1. `format_cache_time()`（`app.py:25-31`）把 ISO 时间里的 `T` 替换为空格，统一成 `YYYY-MM-DD HH:MM:SS` 展示约定；
2. 首页读 `list_datasets()` 失败时静默降级（`app.py:34-37`）——首页永远可用，即便 SQLite 损坏；
3. "最近交易日"取的是所有数据集 `last_trade_date` 的最大值（`app.py:45-47`），因此它反映的是"本地缓存里见过的最新交易日"，不是"今天"。

## 潜在错误

- 首页的"最近缓存更新时间"取 `datasets` 表按更新时间倒序的第一行，任何一次无关写入（例如微盘股快照）都会刷新这个值，用户可能误以为"行情刚更新过"。
- `app.py` 文案"22日动量轮动回测"硬编码了默认参数 22 日，若轮动默认周期改变，文案会失真。

## 改进方法

- 给首页状态卡补充"分市场最新正式日期"（读 `index_final_history` 各指数最新日），比单一 max 更有信息量；
- 把"今日重点"从硬编码文案改为读取 512890 停车状态与当前 MA 信号的一行摘要，让首页成为真正的每日驾驶舱（保持轻量）。

## 实际案例

用冻结参数（`config/frozen_strategy_20260728.json`，十只 ETF 各 10%）在真实缓存上重放组合回测（`run_portfolio_timing_backtest`，区间 2025-02-27 → 2026-09-02，初始 10 万元、单边 0.006%、100 股整手）：

| 指标 | 择时组合 | 一直持有基准 |
|---|---|---|
| 总收益率 | **+36.27%** | +25.60% |
| 年化收益率 | 22.71% | 16.26% |
| 最大回撤 | **-4.87%** | -12.17% |
| 夏普比率 | 2.02 | — |
| 交易次数 | 128（平仓 62，胜率 51.61%） | — |

这就是本书全部章节要解释的对象：+6.44 个百分点的年化超额与回撤减半，是靠什么样的数据管道、信号定义、执行假设和参数纪律换来的，以及它有哪些隐藏的坑。
