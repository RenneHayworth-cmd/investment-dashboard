# 第二十五章 多品种工具箱：期货价差、期权分析、相关性、美股与微盘股

## 理论

主策略（MA 择时）之外，系统维护一组"感知工具"：价差监控（跨期结构）、期权链（波动与持仓）、相关矩阵（分散度证据）、美股日线（对标）、微盘股快照（拥挤度代理）。它们不产生交易信号（微盘股除外，见第 10 章指数卡），但为组合决策提供上下文。本章按模块逐个拆解。

## 数学原理

### 价差

`calculate_spreads(data, base_contract)`：outer merge 按日期 → 逐列 ffill → **截止日置 NA**（每个合约的 `effective_last_date = min(该合约最后数据日, personal_investor_cutoff)`，之后置 NaN）→ `spread = base_close − other_close`、`spread_pct = spread/base×100`（round 4）。截止规则只对铁矿石 `I` 合约：到期月前一月最后一天（个人投资者限仓前必须离场），`spread_respects_contract_cutoffs` 校验"截止日后相关 spread 列全为 NaN"作为缓存有效性条件之一。

### 相关性

`calculate_price_correlation(items, method="price"/"return")`：全标的 inner merge 对齐 → dropna → `method=="return"` 时 `pct_change()`（inf→NA→dropna）→ `DataFrame.corr("pearson").round(4)`。有效起点 = **最后一个首日**（内联对齐的固有性质，页面不提供手动日期窗——AGENTS.md 明文）。r 的定性分档：|r|<0.2 很弱 / <0.4 较弱 / <0.6 中等 / <0.8 较强 / ≥0.8 很强。

### 波动率与百分位（期货/期权摘要）

20 日涨跌、20 日波动率（日收益 std）、价格百分位（`expanding().rank(pct=True)`——**历史全窗百分位**，非滚动窗）。

## 当前项目实现

41 个品种前缀中文映射（IC/IF/IH/IM/T/TF/TS/TL + CU…LC）、`SPREAD_CALCULATION_VERSION="futures_spread_v2"` 缓存版本守卫、`fetch_futures_daily` = TickFlow 与 AkShare/新浪直连**取最新日期较大者**（`choose_latest_futures_daily`）、`prefer_realtime_snapshot` 时 `append_futures_spot_row` 补当日（仅交易日且 quote 为今天）。页面缓存键 `futures_spread_{base_contract}`（**只含基准合约**——同基准不同对手方共用一个缓存文件，靠列校验+版本+cutoff 检查判定失效后重算覆盖）。页面默认 `IM2606 IM2612`、并发 5。

## 代码分析

价差的"截止日置 NA"是全模块最精妙的三行：到期合约的 ffill 值在截止日后是**虚构价格**（合约已不存在），直接参与价差计算会产生"幽灵价差"。置 NA 后 `dropna(subset=spread_cols)` 把截止日后的行整体剔除——缓存校验函数再反向验证这一点，两道闸门确保"价差曲线不会延伸到合约死后"。

相关性自动补算的双刃：`pd.read_csv` 绕过锁与元数据（快），但绕过了 `_adjust_mode` 校验——若缓存目录混入旧版文件，补算用的是未声明口径的数据。分组渲染时"新计算后渲染合并保存矩阵而非独立的当前矩阵"（AGENTS.md）保证了跨会话连续性。

微盘股的"排名"由 `(快照日期, 市值)` 排序后组内 `cumcount` 重算——**快照内排名与当时抓取的排名解耦**，即使东财排序口径变化，历史快照的排名序列仍然自洽。

## 潜在错误

1. 价差缓存键只含基准合约：切换对手方组合会**覆盖**同一缓存文件的列（旧对手方的价差列消失）——靠 `cache_matches_contracts` 的列检查兜底，但"查看 A-C 后切回 A-B"多一次全量重算；
2. 期权缓存保存键固定用 `raw_code` 生成：若实际命中的是规范化候选键，可能产生重复缓存条目；
3. `normalize_price_dataframe` 的列识别是**子串**匹配：同时存在"收盘价/前收盘价"且后者在前会误选（`_find_column` 在 fund_analysis 里有"先精确后子串+跳过 `_` 开头"的加强版，correlation 版是弱化版——两个实现不一致）；
4. 相关性自动补算在每次打开页面都可能新增行（判重只在本组内）——`correlation_results` 表有重复累积风险；
5. 微盘股 `fetch_microcap_stocks` 分页中途失败**静默返回部分数据**（已拿到几页就返回几页）——快照可能是不完整的成分集且无标记；
6. 美股页多代码输入只取第一个（warning 提示）。

## 改进方法

- 价差缓存键改为 `f"{base}_vs_{sorted(others)}"` 的规范串；
- correlation 的 `_find_column` 换用 fund_analysis 的加强版（单一实现）；
- 自动补算加"已补 pair 全局判重"（查 correlation_results 相同 source_summary 的既有行）；
- `fetch_microcap_stocks` 部分失败时在返回 df 上打 `_partial=True` 标记，快照拒绝保存部分集；
- 期权缓存键统一走规范化后的符号。

## 实际案例

三个工具的真实用法串联：① 早上看指数监控发现 `微盘股` 偏离率 +8.83% 全场最高（2026-08-14 快照）→ ② 打开 `微盘股` 页看真实成分快照的"第 200 名市值"与"微盘20均值"曲线是否同步陡升（拥挤度确认）→ ③ 打开 `相关性分析` 用 `159552 512100 932000`（中证2000 增强ETF vs 其标的指数）看跟踪相关是否 ≥0.99（若掉到 0.95 以下说明增强偏离或数据问题）。同一套小盘风险，三个独立视角交叉验证——工具箱的意义不是单点结论，而是**让每个结论都能被第二条证据链复核**。
