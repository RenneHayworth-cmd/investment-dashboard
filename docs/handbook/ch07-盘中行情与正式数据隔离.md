# 第七章 盘中行情与正式数据的隔离：index_realtime.py

## 理论

盘中报价的价值在于"现在"，它的毒性也在于"现在"：一个 14:58 的价格如果被写进日线历史，MA20、回撤、区间收益从此全部失真。隔离的工程原则有三条：

1. **存储介质隔离**：盘中价只进进程内存与会话状态，日线缓存（CSV+SQLite）的写入代码路径与报价代码路径完全不交叉；
2. **时间闸门隔离**：写入正式日线的时间判定（`latest_settled_trade_date`）独立于报价可用性判定（`_market_is_open`），二者不可互相借用；
3. **展示层防回退**：任何把报价套到展示数据的操作，都必须拒绝"报价时间早于缓存最新日"的行情。

## 数学原理

开市判定的区间覆盖：

$$\text{open}(t) \iff \exists i:\ s_i \le t \le e_i \quad (\text{含边界} \le)$$

期货夜盘归属：当 $t \in [00{:}00, 02{:}30]$ 时，检查**前一自然日**是否 A 股交易日（夜盘属于前一交易日的交易时段延续），否则检查当天——这是 `AU0/AG0/SC0` 会话表（0:00-2:30 与 21:00-23:59:59）与 `_futures_market_is_open` 配合的归属规则。

涨跌幅的两种来源：行情源直接给 `f170`（涨跌幅字段），或由 $p / p_{\text{prev}} - 1$ 自算；新浪期货 spot 端点会把现价 echo 到 `last_close` 字段（`_fetch_futures_quote` 第 750 行注释），因此 `previous_close` **故意返回 None**，让上层用正式日线昨收——这是一个典型的"数据源说谎时宁可少给字段"的防御。

## 当前项目实现

`services/index_realtime.py`（878 行，全项目最大的单一服务文件）承担四件事：

1. **实时报价引擎**：`fetch_realtime_index_quotes(*, now=None, max_workers=8, force_index_names=None)` 并发抓取；不带 force 时只拉**开市中**的标的；每个 future 异常吞掉（报价失败不该拖垮整页）。
2. **进程内存缓存**：`_RUNTIME_QUOTE_CACHE + Lock`，`remember_runtime_realtime_quotes / load_runtime_realtime_quotes`——浏览器刷新后能恢复上一轮报价，进程重启即失（刻意不落盘）。
3. **正式日线待补清单**：`find_pending_post_close_index_names`（三条件：最新日 < 目标日 / 20 交易日缺口 / 校正层未到目标日）、`manual_quote_request_names`（手动刷新清单 + 午休去重 key `"{name}:{date}:lunch"`）、`find_final_close_quote_names`（**严格 >** 收盘时刻，一次性抓"最终收盘价"）。
4. **期货主连合约推断**：`_infer_main_contract_symbol` 用正则 `^{prefix}\d{4}$` 选候选，按「与参考价差 → 持仓差 → 成交量差 → 持仓降序 → 成交量降序」排序；映射持久化到 `index_futures_main_contracts`（全量 merged 覆盖写）。

常量表：`EASTMONEY_QUOTE_SECIDS` 16 个（上证 `1.000001` … KOSPI `100.KS11`）、`YAHOO_QUOTE_SYMBOLS`（`^IXIC`/`^VIX`）、`FUTURES_QUOTE_SYMBOLS`（IC0/IM0/I0/AU0/AG0/SC0）、`FUTURES_TRADING_SESSIONS`、`POST_CLOSE_DAILY_DELAY=10min`、`INDEX_SOURCE_LABELS` 9 个中文标签。

## 代码分析

`apply_realtime_quotes_to_summary(summary_df, quotes)` 是展示层套用的唯一入口，三道防线值得抄录：

1. 在 summary **副本**上操作（永不改缓存对象）；
2. 只覆盖 `收盘价/前收盘价/当日涨跌幅(%)/日期` 四列并追加 `实时来源/实时时间` 两列——覆盖面显式枚举，不会污染 MA20 等衍生列；
3. **防回退**：`quote_time.date() < 缓存日期` 则跳过该 quote——哪怕行情源抽风给出昨天的"实时价"，也不会把卡片拉回旧值。

`_daily_update_target`（正式日线目标日）：

```python
target = latest_settled_trade_date(market, now, settlement_delay=POST_CLOSE_DAILY_DELAY)
# 期货夜盘开盘中且目标==今天 → 回退 previous_trading_day
```

这个回退是 878 行文件里最重要的 3 行：夜盘 21:00 后，`latest_settled` 会把"今天"判为已结算日（A 股日盘 15:00+10min 已过），但此时今天的**日盘收盘价**才是想要的正式数据、而夜盘进行中意味着"今天"尚未真正走完——对 I0/AU0/AG0/SC0 这些夜盘品种，目标日回退到前一交易日才能避免把夜盘时段误当成新交易日。

## 潜在错误

1. **进程级缓存的多进程盲区**：`_RUNTIME_QUOTE_CACHE` 与 `_RUNTIME_ETF_QUOTE_FETCH_STATE` 都是进程内存；Streamlit 以多 worker/多进程部署时各进程各有一份，午间"只抓一次"闸门会失效（本机单进程部署无此问题，但部署形态改变即踩坑）。
2. `_market_is_open` 的边界 `<=`：恰好 15:00:00 整点仍算开市，与收盘抓取的 `>` 判定错开 1 秒级窗口——无实害，但依赖两端约定成对出现。
3. `fetch_futures_main_contract_names` 的合约映射是全量覆盖写：若推断一次失误（例如结算数据异常导致选错合约），旧映射被覆盖，需要下一次成功推断纠正；期间"当前具体合约"日线缓存会开始积累错误合约的历史（append-only 反而放大了错误停留时间）。
4. Yahoo 实时 `chartPreviousClose` 自算涨跌幅在除权日会失真（分母是未除权昨收）。

## 改进方法

- 内存缓存加 TTL 与"来源+时间戳"元数据，供 UI 展示"这份报价几岁了"；
- 合约映射覆盖写改为带日期戳的追加审计（保留最近 N 次推断记录），出错可回溯；
- Yahoo 除权日涨跌幅改用 `meta.previousClose`（交易所口径）而非 chart 首行。

## 实际案例

指数监控页的真实交互序列（2026-08-14 收盘后）：15:05 用户打开页面 → 30 秒 fragment `watch_scheduled_index_cache` 发现缓存签名变化（计划任务 15:10 已写入）→ 整页重绘展示正式数据；同一时刻 `find_final_close_quote_names` 早已在收盘时刻之后抓过一次"最终收盘价"供卡片展示，而正式日线更新由计划任务完成——**同一份收盘价，两个来源，各自走各自的隔离通道**。铁矿石价格告警（`scripts/monitor_iron_ore_price.py`）也复用 `_fetch_futures_quote("铁矿石主连","I0")` 与 `_futures_market_is_open`，但它的输出走 ServerChan/Hermes 推送与 `output/alerts/*.json` 状态文件，同样不触碰任何行情缓存——隔离原则在告警场景同样成立。
