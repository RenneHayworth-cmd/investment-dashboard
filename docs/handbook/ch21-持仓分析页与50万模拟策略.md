# 第二十一章 持仓分析页与 50 万模拟策略：position_performance + components/position

## 理论

回测解决"策略是否值得信"，持仓页解决"**今天该做什么**"。`持仓分析` 页把三件事压进一个页面：固定持仓的实时卡片与择时表、512890 停车状态、以及一台**从 2026-08-05 起步的 50 万元模拟策略**——用正式日线逐日重放"如果我严格执行这套参数组合，账户会怎样"，并用盘中预判生成当日可执行的交易清单。它的定位介于回测与实盘之间：**比回测新（吃到昨天收盘）、比实盘干净（不写台账）**。

## 数学原理

### 50 万策略的口径（AGENTS.md 明文）

- 起始：2026-08-05，50 万元，NAV=1；单边费 0.006%（`POSITION_TIMING_TRANSACTION_COST=0.00006`）、100 股整手、同收盘执行；
- **入场规则**（fresh_buy）：只买当日信号为"买入"的标的；初始"持有"的标的不买，必须先空仓再等买入；初始空仓等待买入；
- 512890 起始 0 仓位；510500/159967/159552 三只停车源的 sleeve 只有在该源**首次买入后又卖出**后才激活承接（`empty_position_activation=after_primary_entry`）；
- 延迟激活的半仓袖套（159501/159655）：激活前两半全现金，首次有效买入一次性建立全部袖套，之后卖出降到长期半；
- **建仓费单列**：`setup_fee = 500000 − 首日账户净值`（首日买 4 只 ≈ 13.41 元），账户资产曲线加回 setup_fee、首行强制 50 万/净值 1——**起始日账户价值恒等于 50 万**，后续费用进每日盈亏；
- 数据：前加复权正式收盘；**首日不完整或完整日 <2 天直接报错**；期望交易日历有缺口即截断到最后完整日并 warning；
- 预判（trade preview）：preview_histories = 正式历史（去今日行）+ 当日实时价，重跑回测得 preview_qty；`delta = preview − formal` 非 0 生成行动（卖出优先排序），**净变化语义**（多袖套同标的买卖对冲后为 0 则不动）。

### 当前持仓重建（_build_current_positions）

按 `(袖套代码, 标的)` 重放交易台账：买入加份额、成本含费；卖出按**移动平均成本**扣减并计 realized；`当日盈亏 = 当前 total_pnl − 前一估值日 total_pnl`；`当日收益基数 = prior_market_value + 当日买入成本`；`成本价 = cost_basis/quantity`。多袖套持同一标的时聚合，`来源袖套` 记持仓袖套集合。

## 当前项目实现

### 服务层（position_performance.py，834 行）

- 常量：`POSITION_TIMING_START_DATE=2026-08-05`、`POSITION_TIMING_INITIAL_CAPITAL=500_000`、`POSITION_TIMING_LOT_SIZE=100`、`POSITION_TIMING_PARKING_SYMBOL="512890"`；
- `_build_allocations()`：10 只权重 ETF（159201=5%，159545/159655/518850/510500/159967/159552/513310/513880=10%，159501=15%）按 `ETF_TIMING_STRATEGIES` 参数生成 allocation，三只活跃源带 `empty_position_symbol="512890"`；
- `build_position_timing_performance(items, *, start_date=2026-08-05, initial_capital=5e5, ...)`：校验 11 只必需 ETF → 期望交易日逐日查缺 → `run_portfolio_timing_backtest`（`RotationInput(apply_slippage=False, trade_lot_size=100)`）→ summary 组装（含 `初始建仓代码`）；
- `build_position_timing_trade_preview(items, quotes, ...)`：七类前置失败（非交易日/已收盘阶段/未到开始日/缺缓存/无效缓存/缺正式日线/期望日不完整）直接 error 返回，**不生成可执行通知**；对每只需 ETF 要求当日有效 quote。

### 组件层（components/position/）

- `coordinator.py`（297 行）：侧边栏（API Key、加载按钮、强制刷新、保存开关、持仓清单、高级参数）→ 点击后 `position_updates_enabled=True` 永久开启 → 逐只加载（进度条）→ 详情路由（`?position_detail=`）→ 调 timing_renderer；
- `performance.py`（418 行）：渲染 50 万区块——metric 网格（策略资产/累计盈亏/累计收益率/当前净值）+ 柱线双轴图 + 三 Tab（策略持仓【可叠加实时行情】/交易明细/每日盈亏）；实时叠加层 `_overlay_strategy_positions_with_realtime` 重算市值与当日盈亏但**不改持仓数量与信号**；
- `cards_tables.py`（259 行）：择时表 HTML 高亮（买入行浅红、卖出行浅绿——A 股配色）、卡片网格（每行 4 列）。

### 非 ETF 持仓：position_derivatives.py（592 行）与详情视图

期货合约、价差对与期权的卡片数据由 `position_derivatives.py` 供给：`load_or_fetch_futures_contract`（缓存 `futures_contract_{code}`；实时预览模式 `append_futures_spot_row(replace_current_day=True)` 增补今日快照，正式模式按已完成期货日截断）、`load_or_fetch_spread`（缓存 `futures_spread_{base}`，`_spread_cache_matches_contracts` 校验列/版本/截止日；metrics 含最新价差/日变化/占比/极值）、`load_or_fetch_option`（多候选缓存键探测）。`refresh_position_derivative_items` 在实时带刷新时以 `force_refresh=True, save_to_cache=False, realtime_preview=True` 批量重载（`max_workers=2`），源无今日数据即进 errors。

详情视图（`components/position/details.py`，614 行）按类别分派：ETF 详情四 Tab（走势：4 行子图 价格+MA20/60/120/250+RSI+20日涨幅+滚动年化，价 >0 且 ≥3 年时对数轴；回撤：当前回撤五卡+峰谷区域图+分段/年度表；摘要；数据）；期货价差详情（价差线+各合约收盘线+摘要）；期权/期货详情（走势+成交量/持仓量双轴）。URL 路由经 `?position_detail=`，`formatting.py` 的 `format_etf_table_value` 统一表格精度（价格 3 位、百分比 2 位，Decimal HALF_UP）。

## 代码分析

**预判的双回测结构**（`build_position_timing_trade_preview`）：

```python
formal_result = run_backtest(histories, end=昨日)     # 正式截至昨日
preview_result = run_backtest(preview_histories, end=今天)  # 含今日实时价
delta = preview_qty(标的) - formal_qty(标的)
```

这个设计的精妙处：**预判差异完全由"今日多出的一根价格"驱动**——两次回测共享全部历史与引擎，delta 只能来自今日信号变化，排除了实现漂移。代价是每 2 分钟（尾盘带）重跑两遍完整回测（11 标的 × 1 个月 ≈ 21 天 × 11 袖套）——计算量小（一个月数据），可接受。

`_build_current_positions` 的 `prior_states` 快照（首个 valuation_date 交易日前）让"当日盈亏"跨重启可复现：不依赖内存状态，完全由 trades + 日期重建。

**实时叠加层与正式层的口径差**（潜在错误 §1 详述）：正式层当日收益基数 = `prior 市值 + 当日买入成本`；叠加层 = `昨收 × 数量`。两者在"当日买入"时不同（正式层含买入成本作分母，叠加层分母为 0 → NA）。

## 潜在错误

1. **当日收益率双口径**：正式层（含当日买入成本）vs 实时叠加层（昨收×数量）同日数字可能不同——AGENTS.md 明文"include same-day added buy cost in the daily-return denominator"是正式层口径，叠加层在当日买入时会显示 NA 或不同值；
2. `_strategy_position_quantities` 的净额合并取整（abs≥0.5 保留）：两袖套一买一卖同数量时 delta=0，预判认为无需操作——符合净变化语义，但实盘若希望保持袖套独立则需分别下单；
3. transaction_cost 不含滑点（`apply_slippage=False`）——同收盘成交假设下无滑点自洽，但实盘以市价单执行会有差异；
4. 预判要求"全部 11 只当日有效 quote"——一只缺失则全天无预判（宁缺毋滥，但尾盘时段一只 QDII 断源会连累全局）；
5. `_expected_a_share_sessions` 无日历时退化为工作日——假日（如国庆）会被当作交易日，产生"缺口截断" warning（有警告，不算静默错）。

## 改进方法

- 叠加层的当日收益基数与正式层统一（昨收×数量 + 当日买入成本），消除双口径；
- 预判的 quote 缺失降级为"该标的按正式价参与、标记降级"，而非全局放弃（给出明显 warning）；
- summary 增加"停车仓当前市值与占比"，让 512890 的存在感在指标层可见（当前只在持仓表里）；
- `初始建仓代码` 之外增加"延迟激活日期"清单，方便核对 after_primary_entry 的激活时点。

## 实际案例

2026-09-03 用正式缓存（截至 9-02）重放 50 万策略的真实结果（`output/handbook_backtest_results.json`）：

```
开始日期 2026-08-05 ｜ 正式数据截止 2026-09-02 ｜ 最新估值 2026-09-02
策略资产 496,000.24 ｜ 累计盈亏 -3,999.76（-0.80%）｜ 净值 0.99200048
持仓市值 222,137.20 ｜ 现金 273,863.04 ｜ 仓位比例 44.79%
初始手续费 13.41 ｜ 后续交易费用 23.36 ｜ 初始建仓 159501/510500/513310/518850
```

13 笔交易讲完了一个月的策略叙事：8-05 建仓 4 只（当日信号为"买入"的只有它们；159501 的 15% 袖套买 17700 份×2 笔=长期半+择时半）；8-14 159967 买入（先空仓后买入的正确路径）；8-18 159545 买入；8-19 513310 卖出（**-1790.88，全月最大单笔亏损**）；8-24 双承接（159967、510500 空仓 → 512890 收停车资金 9.6 万）；9-02 159545 卖出（-5.98，几乎打平）。最终 5 只空仓袖套里两只的钱停在 512890。**-0.80% 的月度结果与"择时=稳赚"的直觉相反，但对照同期持有基准的回撤与第 10 章 7 月指数下段背景，这正是系统在右侧确认前付的"等待成本"**。每日尾盘（14:50/14:54）计划任务会把预判 delta 推到微信，页面与通知共享同一台预判引擎。
