# 第十七章 多基金动量轮动：fund_rotation_momentum.py

## 理论

动量轮动是 MA 择时的镜像问题：MA 问"该不该持有"，动量问"该持有**哪一个**"。经典动量（Jegadeesh & Titman 1993）用过去 N 日收益排序，买最强、定期换仓。本项目的默认配置是"22 日动量、持仓 1 只、每周一/每月 1 号调仓"，并提供两种成交模式：

- **after_close（默认）**：调仓日收盘后算动量、按**当日收盘价**成交——依赖 2026-07-06 全市场推广的盘后固定价机制，报告必须披露"earlier history under this mode is a current-rule simulation"；
- **next_open（对照）**：用**前一交易日**收盘信号（signal_lag=1），次日开盘成交，场内 ETF 加双边滑点 ±0.05%。

## 数学原理

动量定义（`_calculate_momentum`）：

$$m_t^{(s)} = \frac{P_t^{(s)}}{P_{t-L}^{(s)}} - 1, \quad L=22$$

实现细节三连：`pct_change(periods=L, fill_method=None)`（停牌不填充，动量在缺口处为 NaN）；`reindex(全日历).ffill()`（停牌期间沿用最后已知动量）；`shift(signal_lag)`（next_open 模式信号滞后一日）。选择规则：动量前 $k$ 名（并列时按 dict 序稳定排序），**只 trade 对称差**（`current_symbols.symmetric_difference(selected_symbols)`）——留仓不动、卖旧买新，现金均分给新进者。

调仓日对齐：周频对齐到**周一**（`_align_rebalance_start` 把目标日推到下一个 weekday==0 再找有效交易日），月频对齐到每月 1 号的下一个交易日；下一次调仓日 `_next_rebalance_date` 生成，找不到有效日时顺延。

**执行缺价延迟**（`_find_tradeable_date`）：需要交易的标的在调仓日无有效执行价时，在 `(调仓日, 下次调仓日)` 开区间内找第一个全部可成交的日子——AGENTS.md 的"missing open price should delay execution only when that symbol must actually be bought or sold"由此实现：**留在选中集的标的缺价不触发延迟**。

## 当前项目实现

`run_fund_rotation_backtest(funds, frequency="week", lookback_period=22, num_positions=1, initial_capital=100000.0, transaction_cost=0.00006, start_date, end_date, execution_mode=after_close) -> RotationResult`。

主循环按调仓计划推进（第 121-256 行），每个调仓日：

1. `value_before` = 调仓前组合市值 + 现金（首次调仓前组合为空，value=cash）；
2. 卖出退出者：`_trade_price` 按 execution_mode 取 `__raw_close` 或 `__open` 列，next_open 且 `apply_slippage` 时买 `×(1+0.0005)`、卖 `×(1-0.0005)`；
3. 留仓者份额与成本基原样带入 `new_shares/new_cost_basis`；
4. 买入新进者：`allocation = cash_value / len(entering)` 均分，先按 `allocation×c` 预扣费再整手取整，实际费用按实际成交额重算（预扣与实扣的差异留在现金里）；
5. 记 `trade_rows`：调仓/持有、选中标的、**全部标的的动量**（不只持仓）、买卖明细字符串（含份额/价格/金额/费用/盈亏）、`调仓前金额/成交后金额/调仓日收盘金额` 三价对照；
6. 调仓间隙逐日记净值（`nav_rows`），`当前持仓` 列记录持仓名称。

结果对象：`nav_data / individual_nav_data / individual_results`（各标的一直持有对照）/ `trades / drawdown / yearly_stats / summary`。

## 代码分析

`_prepare_merged_data`（fund_rotation_data.py）把多标的宽表化为 `trade_date + {symbol}__raw_close + {symbol}__open` 列——`__raw_close` 这个命名暗示它**优先用未复权价**（open 列是真实开盘价）。动量用 raw_close 计算，与前复权口径的差别只在除息日附近（差值复权下除息日 raw 收益率含分红坑，比例复权不含）——**动量窗口 22 日跨越除息日时，raw 口径会低估该标的动量**，对高分红 ETF（512890 等）有轻微排序偏置。

`_build_rotation_plan`（381-425 行）的冷启动处理：`momentum_cache.loc[scheduled_date]` 若调度日不在动量索引（极端对齐失败）用空 dict → `len(selected) < num_positions` → `continue` 跳过该期——首期永远从动量完整可用的日期开始（`_get_start_date` 保证），因此不会系统性丢失首期。

卖出盈亏的记账：`sold_cost_basis` 累计本期卖出者的成本基，`本次交易盈亏率(%) = realized_pnl_total / sold_cost_basis`——**聚合口径**（一次调仓的所有卖出合并成一笔盈亏），AGENTS.md 的"rotation rows aggregate all positions sold in that rebalance"由此实现；`sell_details` 字符串里保留逐标的明细。

## 潜在错误

1. **after_close 的历史合法性**：2026-07-06 之前的"盘后固定价成交"是现行规则反推的历史模拟——引擎自己无法区分，报告层必须披露（summary 的`成交假设`键 + AGENTS.md 要求）；
2. **动量的 ffill 泄漏边界**：停牌标的的动量 ffill 到复牌日，复牌日若暴涨 20%，动量仍是停牌前的旧值——排序低估复牌标的（保守方向，可接受但应知晓）；
3. `allocation` 均分后整手取整的现金碎片：每只新进标的的取整余数留在现金池，`num_positions` 大且价高时碎片可观（如 10 万元买 2 只 700 元/份标的会各留数百元）；
4. `_calculate_momentum` 的 `fill_method=None` 在 pandas 2.x 起是显式必需——依赖版本行为，跨 pandas 大版本升级需回归测试；
5. 动量并列时的 dict 序稳定性依赖 `momentum.items()` 的插入序（`source_data.keys()` 顺序），换个输入顺序选股可能不同——非随机但未文档化。

## 改进方法

- 动量计算增加"复权口径"开关（默认比例复权收盘价），消除除息偏置；
- 现金碎片在下次调仓并入 allocation（当前每期重新均分，碎片自然回池——已经如此，可加一行注释说明）；
- `trade_rows` 的动量列改为"前 N 名 + 动量值"结构化输出，便于后续做归因分析；
- 增加 `max_turnover` 参数（单期最多换 M 只）模拟人工执行约束。

## 实际案例

一个可直接心算验证的执行链：假设 5 只 ETF 候选、22 日动量、持仓 1 只、每周一调仓。2026-08-03（周一）某次调仓：动量排序 `513310 +38.2% > 588000 +29.6% > ...`，选中 513310；当前持仓 510500 → 对称差 = {513310, 510500}；513310 当日有有效 raw_close（4.888）→ 执行日=当日；卖 510500 @7.74 扣 0.006% 费，现金均分后按 100 股整手买 513310。这套流程的真实输出结构可见策略回测页"多基金动量轮动"模式；其结果的完整性依赖第 3-8 章的数据层——**轮动回测对数据缺口最敏感**（任何标的一段 NaN 都会通过动量 ffill 与执行延迟机制扭曲排序），这也是它默认"缓存优先、刷新可选"而单标的 MA 回测"每次强制联网"的原因：轮动吃的是长而全的历史，MA 择时吃的是新鲜的尾部。
