# 第十章 指数 MA20 引擎：index_ma20 / index_signals / index_frames / index_history

## 理论

指数监控页回答一个每天都要问的问题："现在各市场相对 20 日均线在哪里？"它的难点不在 MA 本身，而在**展示语义**：

- 偏离率要排序（谁离均线最远）；
- 每个历史行要显示**当时**的状态转变日期与从转变日收盘起算的区间涨幅——不是全表重复当前转变（AGENTS.md 明文："do not repeat only the current transition metrics across all historical rows"）；
- 汇总表要同时给出**上一段完整区间**的收益（从上一转变日收盘到当前转变日收盘）——"上一段赚了多少"比"这段赚了多少"更能评估一次信号的质量；
- VIX 进卡片和详情，但不进 MA20 汇总表（`show_ma20_deviation=False`）。

## 数学原理

对每个交易日 $t$，定义上方状态 $a_t = \mathbb{1}[P_t \ge M_t]$（展示版含等号）。转变事件集 $E = \{t: a_t \ne a_{t-1}\}$。对任意 $t$：

- 当前转变日 $\tau(t) = \max\{e \in E: e \le t\}$；
- 区间涨幅 $R(t) = P_t / P_{\tau(t)} - 1$（**从转变日收盘起算**，含转变日当天收益）；
- 上一转变日 $\tau'(t) = \tau(\tau(t)-1)$（转变日序列的前一个）；
- 上一区间完成收益 $R^{\text{prev}}(t) = P_{\tau(t)} / P_{\tau'(t)} - 1$——**在转变日已封口**，永不变化。

实现上全部向量化（`index_signals.py:162-223`）：`is_transition = a.ne(a.shift()) & a.shift().notna()`，转变日收盘 `where(is_transition).ffill()` 得分母，$R(t)$ 一行除法完成；上一段收益用"转变日收盘 ÷ 转变日收盘.shift(1) − 1"在事件点上计算后再 `ffill()` 广播回全表。

## 当前项目实现

### index_config.py（215 行）

22 个指数的配置表（第 5 章已详述）。补充展示相关常量：`INDEX_REPORT_DISPLAY_DAYS=120`（分列报表固定保留最近 120 自然日，无用户可选窗口）、`INDEX_LONG_HISTORY_BARS=20000`。

### index_signals.py（226 行）

- `build_summary(report_df)`：从分列报告提取每指数的 `收盘价/MA20/偏离率/状态转变时间/区间涨幅/上一状态转换时间/上一区间涨幅`。优先读报告中已算好的列，缺失时回退 `calculate_ma20_transition_snapshot` 现算；当日涨跌幅由最近两行收盘自算。
- `sanitize_index_report_market_dates`：对每个指数按其市场日历把**非交易日行的该指数列全部置 NA**（跨市场报表的对齐清洗：A 股假日里港股的行必须有数、A 股列必须为空），再删全空行。
- `calculate_ma20_transition_history`：向量化转变史（见上），返回四列可对齐回原索引。

### index_frames.py（309 行）

报告的合并与裁剪工具：`merge_index_report(existing, update, prefer_update_index_names)`（existing keep=first、update keep=last、`combine_first` existing 优先）、`trim_index_report(df, days=120)`、`extract_cached_index_report`（取 `日期` + `f"{index}_*"` 列）、`latest_index_trade_date`、`has_current_index_quote`。

### index_history.py / index_ma20.py（门面）

`fetch_index_history(index_name, index_config, days=10000)` 为详情页拉长历史（本地缓存叠加层优先，缺才联网）；`index_ma20.py` 是兼容门面，聚合上述模块。

### 详情页指标（pages/1_指数监控.py）

单指数详情算 MA5/20/60/120/250、偏离率、日涨跌、累计涨跌、`cummax` 历史高点与回撤、RSI14（SMA 口径，与 `calculate_rsi` 一致——**不是** Wilder 平滑）；区间 segmented_control：近一年/今年来/近3年/5年/10年/成立来。

## 代码分析

`calculate_ma20_transition_history` 有两处精心设计值得注意：

1. **`is_above.shift().notna()` 排除序列头部的伪转变**：MA 前 19 行为 NaN，`a` 从第二十行才有定义；`a.shift()` 在第二十行是 NaN，`ne` 会误判为转变——`& a.shift().notna()` 把它滤掉。若不滤，每个指数都会有一个虚构的"第一天转变"。
2. **`transition_close = close.where(is_transition).ffill()`**：区间收益的分母是**转变日收盘价**，而不是转变日前一日收盘。这意味着转变日当天的涨跌计入新区间——与"信号在转变日收盘生效"的回测口径一致，展示与回测可对照。

`build_summary` 的回退链（第 76-97 行）：报告列存在且非空 → 直接用；否则 `calculate_ma20_transition_snapshot` 现算。这让"旧报告缓存（没有上一段字段）+ 新代码"能平滑过渡——向后兼容的字段级演化。

## 潜在错误

1. **展示版与回测版等号不一致**（第 9 章已提）：`>=` vs `>` 在零偏离点上状态相反；
2. `sanitize_index_report_market_dates` 对 `market_group` 缺失的指数跳过清洗——配置错误的指数会带着周末日期混进报表；
3. 120 自然日窗口是**自然日**而非交易日（约 82 个交易日），分列报表在长假后会丢掉长假前早期数据；这是有意为之（AGENTS.md 规定），但读者需知道"窗口按日历裁剪"；
4. `build_summary` 的当日涨跌幅在报告只有一行时为 NA（无法自算），卡片显示"-"——正常但容易被误读为停牌。

## 改进方法

- 把转变史计算挪到 `numpy`（`np.sign` + 边界 `flatnonzero`），120 日 × 22 指数的即时重算完全无感；
- `sanitize` 的缺失 `market_group` 给 warning 而非静默跳过；
- 汇总表可加"当前区间已持续天数"列（今天 − 转变日），对判断趋势"年龄"很直观，成本为零。
