# 第十二章 512890 停车 ETF：聚合状态机与空仓资金承接

## 理论

择时策略最大的心理成本是"空仓看着行情涨"。停车（parking）设计把"择时 ETF 的空仓资金"自动停进一只**低波动、高分红、与源资产低相关的 ETF**（512890 红利低波），实现两个目标：

1. **资金不停摆**：空仓期拿红利低波的车位收益，而不是活期；
2. **状态语义简单**：聚合状态只看"有没有源空仓"，0% 与 30% 之间不产生中间叙事。

关键设计约束（AGENTS.md）：**聚合状态转换只在 0%↔非 0% 时发生**；中间的权重变化（1 只源空仓→2 只源空仓，10%→20%）**不算新转换、不重置区间收益**。这避免"权重每变一次就重写一次业绩起点"的数学污染。

## 数学原理

设三只活跃源 $s \in \{510500, 159967, 159552\}$ 各占组合 10%，各自择时仓位 $w_s(t) \in \{0,1\}$。定义：

- 停车权重 $W(t) = 10\% \times \#\{s: w_s(t)=0\} \in \{0\%, 10\%, 20\%, 30\%\}$；
- 聚合状态 $A(t) = \mathbb{1}[W(t) > 0]$（任一源空仓即"停车持有"）；
- 转换集 $E_A = \{t: A(t) \ne A(t-1)\}$，区间收益从 $E_A$ 的转换日收盘价起算。

**为什么状态是布尔而非权重本身**：若用 $W(t)$ 做转换判定，510500 与 159967 相隔三天先后空仓会产生两次"转换"，每次都重置收益分母——而实际上 512890 的持仓从未清零，区间收益的概念被人为切碎。布尔化后只有"从全满到有车位"与"从有车位到全满"两个真实边界。中间权重变化对收益的贡献自动包含在"当前区间涨幅"里（因为分母固定在首次转换日）。

回测中的承接时序（`fund_rotation_timing._run_delayed_timing_sleeve`）：**同日收盘**先卖源、后买 512890（`reason=f"{item.symbol} 卖出后转入空仓承接标的"`），无滑点、有手续费、整手 100——零空隙，资金当日即停进车位。

激活策略 `empty_position_activation`：
- `immediate`：源一开始就空仓就直接买 512890（策略回测页默认）；
- `after_primary_entry`：源必须**先真实建仓过**，之后的空仓才承接（50 万模拟用这个，防止"开局全空仓=全额停 512890"的失真）。

## 当前项目实现

三处实现（口径对照）：

1. **快照版** `position_timing.calculate_512890_parking_snapshot(items)`（第 226 行起）：
   - 三源序列 `_calculate_etf_timing_position_series` → `combined_positions` 按日期对齐、从 `first_common_ready_date`（三序列起始日最大值）截断、`ffill().dropna()`；
   - `parking_states = combined_positions.eq(0).any(axis=1).astype(int)`——**任一源为 0 → state=1**；
   - 遍历生成转换序列（state 翻转时记 date/state/price，price 用 512890 当日收盘）；
   - **实时叠加**：从各源 `metrics["择时判断"]` 现算 `empty_source_count`，若 `current_date > formal_latest_date 且 current_state != formal_latest_state`，追加一条合成转换（price 用 512890 的最新价，可能来自实时行情）；
   - 有效性闸门：任一源缺失或 `formal_history_valid=False` → 占位快照（全 "-"）。
2. **回测版** `position_performance._build_allocations`：三源 allocation 设 `empty_position_symbol="512890"` + `after_primary_entry`；512890 自身是 `hold` 10%。
3. **指引版** `build_recent_etf_operation_guidance`：卖出标的 ∈ `ETF_512890_TRANSFER_SOURCE_CODES`（5 只全集）且权重>0 → 记入 `parking_buys[日期]`，随后生成"承接…"行（**与 1/2 的活跃集口径不一致**，第 11 章已列）。

权重来源：`ETF_PORTFOLIO_WEIGHTS_PCT` 中三源各 10%；`ETF_512890_ACTIVE_TRANSFER_SOURCE_CODES = ("510500","159967","159552")`。

```python
current_state = 1 if empty_source_count > 0 else 0

```

合成转换**只用于展示**，不回写任何缓存——与全系统"实时层不持久化"的铁律一致。`组合权重比例 = f"{empty_source_count*10}%"` 直接由空仓源数生成，源不齐时显示 "-"（宁可空白不给错数）。

回测版袖套（`_run_delayed_timing_sleeve`）里承接的完整生命周期：`fallback_shares/fallback_cost_basis` 两个状态变量独立于主仓记账；源重新买入时**先卖 512890 再买源**（"信号重新买入"分支），reason 字符串区分三种路径（首次买入退出承接 / 空仓转入承接 / 重新买入退出承接），交易明细里的 `原因` 列就是靠它可读的。

## 潜在错误

1. **口径分裂**（承接行 5 只 vs 快照/回测 3 只）：已列为全项目最值得修的一致性问题。
2. **合成转换的日期取最大值**：`current_date = max(各源 latest_date, 512890 latest_date)`——若某源缓存异常偏新（例如带入了未确认行），会凭空产生一个"未来的"转换时间。
3. **`_timing_action_position` 把"降至半仓"映射为 0**：当前三源都是纯择时无碍，但若未来把某只半仓 ETF 加入活跃源，停车逻辑会把"半仓"当作"全空仓"承接 10%——一处埋着的地雷。
4. 停车快照对 `parking_prices.get(date)` 缺失（512890 停牌日）静默跳过转换价，区间收益分母可能沿用更早的转换价，跨停牌区间的涨幅被放大或缩小。

## 改进方法

- 统一三处承接口径（活跃集为准），预留源单独标注；
- 合成转换加"预判"标记列，UI 显示"实时预判转换"与正式转换区分；
- `_timing_action_position` 对半仓词显式抛错或返回 None 而非 0；
- 512890 停牌日的转换价缺失显式记 NA 并停更区间收益。

## 实际案例

2026-08-24 的真实承接（50 万模拟策略成交明细，`output/handbook_backtest_results.json`）：

```
2026-08-24  卖出 159967 创业板成长ETF   59900份 @0.779  金额 46662.10  手续费 2.80  盈亏 -3300.30
2026-08-24  买入 512890 红利低波ETF    39200份 @1.189  金额 46608.80  手续费 2.80  （159967 袖套承接）
2026-08-24  卖出 510500 中证500ETF     6300份  @7.740  金额 48762.00  手续费 2.93  盈亏  -478.38
2026-08-24  买入 512890 红利低波ETF    41600份 @1.189  金额 49462.40  手续费 2.97  （510500 袖套承接）
```

两个袖套各自独立：卖 159967 的钱只买 39200 份 512890，卖 510500 的钱只买 41600 份——**袖套间不混合现金**。当日 512890 收到约 9.6 万元停车资金（占账户 19.2%，对应两只源空仓 = 20% 权重，与快照"组合权重比例 20%"一致）。到 2026-09-02，停车快照显示区间 +1.01%——停车仓本身小幅上涨；同期 159545 又在 9-02 卖出（-5.98 元基本打平）。**停车机制的收益路径就是这样一砖一瓦砌起来的**：单笔都平淡，但空仓期从 0% 收益变成 +1% 区间，长期复利的差异就在这里。
