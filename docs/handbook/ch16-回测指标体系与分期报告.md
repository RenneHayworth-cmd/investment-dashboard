# 第十六章 回测指标体系与分期报告：metrics / summary / 期间表

## 理论

指标的杀伤力在于**口径**：同一份净值，"回撤从哪天起算""年化用自然日还是交易日""波动率分母是 n 还是 n-1"的不同回答能差出几个百分点。本项目的指标层（`fund_rotation_metrics.py` + `fund_rotation_summary.py`，合计 300 行）把口径钉死在四个原则上：

1. **播种（seeding）**：收益序列以初始资金为第 0 项——首日费用进收益，回撤峰从 $V_0$ 起算；
2. **自然日年化**：$(1+R)^{365/d}-1$，$d$ 是首尾日期的自然日差；
3. **√252 波动率**：日收益标准差（样本口径 ddof=1）×√252；
4. **只数已平仓**：胜率、盈亏统计只计完整买卖对，未平仓头寸不进胜率。

## 数学原理

- 回撤：$\text{DD}_t = V_t / \text{cummax}_t - 1$；年最大回撤在**年度内重置峰值基线**（`_calculate_yearly_stats` 用 `previous_year_end` 播种年度序列，再对播种序列做 cummax——年度回撤的上年是峰）。
- 夏普（无风险利率=0 版本，`_calculate_sharpe_ratio`）：$\text{SR} = \bar r_d / \sigma_d \times \sqrt{252}$；年度组合引擎的版本带无风险利率：$\text{SR} = (\bar r_d - r_f^d)/\sigma_d \times \sqrt{252}$，$r_f^d = (1+r_{\text{年}})^{1/252}-1$（`annual_etf_selection.performance_metrics:364-369`）——两套夏普并存，口径各自声明。
- 交易胜率：$\text{win} = \frac{\#\{\text{卖出盈亏}>0\}}{\#\{\text{卖出}\}}$。
- 超额收益的两种表达：策略页用 `超额收益(%) = 总收益差 ×100`（百分点混淆警告：它其实是差值的百分数表述）；组合页用 `年化超额收益(百分点) = (年化策略 − 年化基准)×100`。

## 当前项目实现

### fund_rotation_metrics.py（163 行）

- `_round_lot_shares(shares, lot_size=100)`：`int(shares // lot_size) * lot_size`，lot≤0 时返回浮点份额（场外基金路径）；
- `_calculate_drawdown(nav_df, initial_capital)`：running_peak `.clip(lower=initial_capital)`（第 9 章的"首日费用不造回撤"）；
- `_calculate_yearly_stats`：年度收益链式基线（上年期末），**跨年回撤不跨年计**；
- `_calculate_sharpe_ratio` / `_calculate_nav_returns` / `_calculate_trade_win_stats`。

### fund_rotation_summary.py（145 行）

- `_build_summary`（轮动版）：含 `成交方式/成交假设` 两个披露键——`after_close` 的成交假设字符串是"按收盘价全部成交，未模拟盘后排队未成交"，`next_open` 是"按开盘价成交，场内标的计入双边滑点"；
- `_build_timing_summary`（单标的版）：30 键全表（第 14 章），其中 `持仓天数/持仓占比(%)` 量化择时的在场时间——512890 示意回测的持仓占比 57.63%，即 42% 的时间在空仓。

### 期间表（components/backtest/*.py）

`build_timing_period_table`：对 `build_standard_backtest_periods(end_date)` 的每期**重跑完整回测**（不是切片净值），行列含"实际开始/实际结束"——短命资产不会假装有五年历史。AGENTS.md 要求的"separate results for 近一年、今年来、近三年、近五年、成立来，anchored to the selected interval's actual final trading date"由此实现。

## 代码分析

**统一指标库 `core/metrics.py`（226 行，当前工作区新增）**是本章所有口径的唯一定义：`seeded_values/seeded_returns`（播种）、`total_return`、`annualized_return`（日历日复利，**总亏损 ≤ -100% 时返回 -1**，修复了旧代码返回 0 的显示误导）、`annual_volatility`（ddof=1 ×√252）、`sharpe_ratio`（带 `risk_free_annual` 参数，按年复利折算到期）、`drawdown_series/max_drawdown`（initial_capital 作为起点峰值计入 cummax——首日费用进回撤）、`longest_underwater_days`（自然日、1e-10 容差、种子峰值日期默认为首个数据点前一天）、`calmar_ratio`、`trade_win_stats`。模块 docstring 明说动机："至少 8 处各自实现……风险利率与极端情形处理不一致"。

`fund_rotation_metrics.py` / `fund_rotation_summary.py` 重构后逐函数委托到 `core.metrics`（键名与输出不变），`annual_etf_selection.performance_metrics` 与 `portfolio_audit_metrics` 同样委托——四套夏普现在来自**同一个函数**，差异只剩各自传入的 `risk_free_annual`（回测页 0、年度组合 1.5% 现金利率）。

播种的精确效果（`core.metrics.seeded_returns`）：

```python
seeded = pd.concat([pd.Series([initial_capital]), clean_values])
returns = seeded.pct_change()   # 首期收益 = V1/V0 - 1，首日费用计入
```

若不播种而用 $V_t/V_{t-1}$，首日收益缺失，回撤序列从第二天才开始，-0.03% 级别的首日费用被漏计。口径 matters：AGENTS.md 明文 "must seed the series with initial capital so first-day transaction costs and slippage are included"。

年度统计的年度回撤算法（`_calculate_yearly_stats`，仍为本模块本地实现）：

```python
baseline = previous_year_end if ... else values.iloc[0]
seeded = concat([Series([baseline]), values])
running_peak = seeded.cummax().iloc[1:]     # 峰值含上年期末
drawdown = values / running_peak - 1
```

年初下跌时峰基线是**上年期末净值**——2026 年内 -4.87% 的回撤就是从 2025 年末起算的，与日历直觉一致。

## 潜在错误

1. **`超额收益(%)` 的单位命名**：`round((total_return - benchmark_return) * 100, 2)` 结果叫"%"，实际语义是"百分点差"——组合页的键名（百分点）是对的，单标的页的键名容易让人把 10.67 读成"超额 10.67%"（其实=总收益差 10.67 个百分点，同一数值两种说法，不算错但易混）。
2. **分期表的重跑成本与一致性**：每期独立重跑意味着"成立来"与"近三年"在重叠区间的交易应当一致——确实一致（同一引擎同一参数），但"今年来"的 MA 预热用的是去年数据（区间裁剪在滚动之后，第 14 章），与"真实按今年开始操作"不同——这正是设计意图，但读者需理解"分期表是同一策略在不同窗口的重放"，不是"把一条净值切成五段"。
3. `_calculate_yearly_stats` 的年度基线在净值序列有 NaN 时（某些引擎输出全 NA 行）会静默错位——组合引擎已过滤 NaN，自定义调用方需自行保证。
4. **夏普口径**：统一库 `core.metrics.sharpe_ratio` 已支持 `risk_free_annual` 参数，但回测页传 0、年度组合传现金利率——**数值不可直接横向比较**，报告层应声明各自口径（键名仍统一叫"夏普比率"）。

## 改进方法

- 单标的 summary 的 `超额收益(%)` 键名改为 `超额收益(百分点)`，与组合页统一；
- 分期表附"预热数据起点"说明列；
- ~~夏普增加 `risk_free` 参数~~——`core.metrics.sharpe_ratio` 已实现；剩余工作是把口径写进各 summary（`夏普口径` 键）；
- `yearly_stats` 增加年度交易次数与年度成本，让"哪一年在磨损"可视化。

## 实际案例

512890 示意回测（MA20/1%）的分期全表（真实重放）：

| 期间 | 策略收益 | 持有收益 | 策略MDD | 交易次数 | 胜率 | 持仓占比 |
|---|---|---|---|---|---|---|
| 近一年 | +0.88% | +0.08% | -8.10% | 9 | 50% | 39.51% |
| 今年来 | -1.20% | +2.39% | -7.23% | 7 | 33.33% | 41.36% |
| 近三年 | -3.20% | +25.63% | -14.89% | 37 | 38.89% | 51.79% |
| 成立来 | +55.66% | +139.48% | -17.14% | 87 | 48.84% | 57.63% |

这张表是指标口径的教科书：**持仓占比**随窗口拉长而升高（57.63% vs 39.51%），说明近一年择时更谨慎（多次空仓躲过 -14% 的持有回撤——近一年持有 MDD -14.16% vs 策略 -8.10%）；**今年来**策略 -1.20% vs 持有 +2.39% 的落后，正是 41% 空仓时间在慢牛里的机会成本。四个窗口讲述四个不同的故事——这就是为什么 AGENTS.md 要求"显示每个期间的实际开始/结束"，拒绝用单一数字概括策略。
