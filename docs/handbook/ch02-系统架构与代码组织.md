# 第二章 系统架构与代码组织：门面模式与模块拆分

## 理论

大型单文件页面是 Streamlit 项目的常见病：一个 `pages/xxx.py` 长到几千行，测试无法定位、mock 无法注入。本项目的解法是**兼容门面（facade）模式**：保持旧的导入路径与函数签名不变（`services/index_ma20.py`、`services/update_tasks.py`、`services/position_analysis.py`、`services/futures_live_trading.py`、`services/fund_rotation.py`、`services/portfolio_audit.py` 等），把实现拆到同名前缀的兄弟模块；页面壳只保留路由，交互下沉到 `components/` 子包。

这带来三个工程收益：

1. **测试可打补丁**：测试 monkeypatch 门面符号后，实现模块仍能看到（通过 `_call()` 依赖注入机制，见下）；
2. **职责单一**：数据源、持久化、编排、校验各自成模块，错误边界清晰；
3. **增量重构**：不必一次性迁移所有调用方。

## 数学原理

本章无数学内容，但架构本身有一条"依赖方向"的形式化约束可以写成偏序：

$$\text{pages/components} \rightarrow \text{services（门面）} \rightarrow \text{services（实现模块）} \rightarrow \text{core} \rightarrow \text{pandas/sqlite}$$

依赖必须单向；门面允许被旧代码与测试依赖，但**服务层不得反向依赖页面组件**（AGENTS.md 明文规定）。

### 门面的两种实现手法

**手法 A：`_call()` 依赖注入**（`position_analysis.py`、`futures_live_trading.py`）。门面在模块尾部用 `_FACADE_DEFAULTS = {name: globals()[name] for name in __all__}` 记录"干净状态"；每次转发调用前，把"被测试 patch 过的依赖名"临时 `setattr` 到实现模块，调用后恢复（`position_analysis.py:91` 起）。这样测试 patch 门面上的 `load_or_fetch_etf`，实现模块内部调用也会命中 mock。

**手法 B：globals 回写**（`update_tasks.py`）。每次函数调用前把门面 `globals()` 里全部同步名回写到四个子模块的 `__dict__`，注释原文："Keep legacy patch targets effective"。

## 代码分析

以 `services/fund_rotation.py`（门面，6987 字节）为例，它转发四个核心入口：

- `normalize_rotation_dataframe(df, fallback_name) -> RotationInput`（实现在 `fund_rotation_data.py`）：识别 `trade_date/日期/date` 与 `close/收盘价/累计净值` 列（先精确匹配再子串匹配），输出 `RotationInput(symbol, name, dataframe, trade_lot_size=100, apply_slippage=True)`；**有开盘价列才启用滑点**——场外基金净值无开盘价，自动免滑点、免整手。
- `build_standard_backtest_periods(end_date)`（`fund_rotation_data.py:67`）：固定返回 `近一年/今年来/近三年/近五年/成立来` 五期，锚点是**所选区间的实际最后交易日**，且每期展示实际起止日，避免"五年期"对短命资产撒谎。
- `run_ma20_timing_backtest` / `run_portfolio_timing_backtest` / `run_fund_rotation_backtest` 分别转发到 `fund_rotation_timing.py` 与 `fund_rotation_momentum.py`。

`components/annual_etf_dynamic.py` 展示了第三种门面手法：**namespace 注入**——把门面模块的 `globals()` 整个作为参数传给 `components/backtest/annual_dynamic.py` 的实现函数，实现里所有 `load_dataset/save_dataset/fetch_annual_*` 都从 namespace 取，从而让旧测试的 mock 继续生效。

## 潜在错误

1. **`_call()` 的盲区**：若直接 patch 门面上被转发的函数本身（`dependency == name` 被跳过），注入不会发生；`_PATCHABLE_NAMES` 还包含 `'annotations'`（来自 `from __future__ import annotations`），快照进默认表后理论上会被 setattr 到子模块——无害但诡异。
2. **签名漂移风险**：`update_tasks.py` 手写重复了 24 个函数签名，位置参数转发顺序必须与实现一致，人工维护易漂移。
3. **`_DIRECT_EXPORTS` 快照绑定**：`futures_live_trading.py` 把 60+ 个私有 helper **复制**进门面 globals，这些副本不受 `_call` 的依赖替换保护，测试 patch 门面符号时与实现行为可能不一致。
4. **namespace 注入的隐式契约**：`annual_etf_dynamic.py` 里实现函数依赖的每个名字都必须出现在门面 import 中，漏一个就是运行时 NameError。

## 改进方法

- 用 `functools.wraps` 包装器自动生成转发函数，杜绝签名重复（手写签名改成 `inspect.signature` 校验一次即可在 CI 拦截漂移）；
- 把 `_DIRECT_EXPORTS` 改为模块属性访问（`_parser._number`），让补丁穿透；
- 为 namespace 注入的门面补一个"名字清单"测试：遍历实现函数 `__code__.co_names`，断言全部存在于 namespace。

## 实际案例

一个真实的排错过程：本手册写作时需要用项目自身代码重放回测，脚本按门面方式导入 `from services.fund_rotation import normalize_rotation_dataframe`，再从缓存 `load_dataset(...)` 读数。第一次在 WSL 运行时全部报"缓存缺失"——原因是 `cache.db` 的 `datasets.file_path` 存的是 Windows 形式路径（`C:\Users\...`），在 WSL 下 `Path(file_path).exists()` 恒为假。这暴露了两条架构事实：

1. `core.cache` 把**绝对路径**写进数据库元数据（`core/cache.py:114`），跨平台迁移缓存目录时元数据会全部失效（数据文件还在，只是"找不到"）；
2. 修复方式不是改数据，而是按门面哲学包一层：`_cache.load_dataset = translated_wrapper`，在原实现读不到文件时按当前 `RAW_DIR` 重新拼路径。门面模式让这种"在边界处打补丁"成为可能——核心逻辑一行未动。

复现脚本见 `docs/handbook/repro_hb_backtest.py`。
