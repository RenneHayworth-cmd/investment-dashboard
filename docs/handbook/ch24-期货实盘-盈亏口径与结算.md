# 第二十四章 期货实盘（下）：持仓、双口径盈亏与结算

## 理论

期货盈亏有**两种都正确但不可混用**的口径：

- **盯市（settlement）**：按交易所**结算价**估值，扣成交手续费 + 行权手续费，**不含申报费等账户级费用**——与同花顺期货通的"全部盈亏（盯市）"一致，是交易者复盘的口径；
- **收盘（close）**：按行情**收盘价**估值，扣全部费用（含申报费、账户费用、月度残差）——是"真金白银"的口径。

两套各自有独立的累计净盈亏、日收益与经济权益，页面所有趋势图/日历都强制选择其一，**永不混用分母与数值**（AGENTS.md："never mix close and settlement amounts or denominators"）。

## 数学原理

### 逐日账本（futures_live_daily_pnl.py，777 行，全项目最重的会计模块）

从第一笔成交/流水日起逐交易日推进，状态机处理：

1. **开仓**：加权平均价；**平仓**：`closed = min(q, available)`，已实现盈亏**优先按持仓链开仓成本重建** `(P - avg)×closed×mult×方向`，仅当期初昨仓（链不完整）才回退结单 `close_pnl`——注释原文："持仓链完整时必须按开仓成本重建已实现盈亏，避免平仓日重复释放浮盈亏"；乘数缺失的成交**整体跳过（连手续费也不计）**；
2. **期权**：带符号数量（买+/卖−）；平仓已实现 = 多 `(价−均)` / 空 `(均−价)`（权利金口径）；
3. **到期**：显式事件优先；无事件时铁矿石期权自动到期判定——实值 put（结算 < strike）多头 `realized += −avg×closed×mult`（权利金全损），**空头被指派 `+avg×closed×mult` 并按 strike 新增多头期货仓**；`expiry > 最新月末 或 无结算价` → pending（当日"数据不完整"）；
4. **费用**：settlement 口径 `+= 成交费 + 行权费`；close 口径 `+= 成交费 + 账户费 + 月度残差`（`residual = 月手续费 − 明细费 − 账户费`，|残差|>0.05 挂到该月最后交易日）；
5. **日行**：`net_pnl = realized + floating − cumulative_fee`（不完整日为 NA）；`economic_equity = 累计净入金 + net_pnl`；`contract_pnl` 单合约明细。

### 收益率分母（两口径同构）

$$\text{base}_t = \text{equity}_{t-1} + \max(\text{net\_cashflow}_t, 0)$$

**只加正入金、出金不减分母**（AGENTS.md 明文"do not reduce the denominator for net withdrawals"）——出金后收益率不会被出金动作虚增或虚减。close 口径断档后的第一个完整日**只重建基线、不产出当日盈亏**（continue）。

### 盯市的手工日盈亏对账

`futures_daily_pnl_overrides`（同花顺补录）核对：`difference = formal_daily − manual_pnl`；`|diff| ≤ 0.05` → **'已一致'且强制 resolution='采用正式'**；否则用已选 resolution 或'待核对'；formal 未生成 → '待确认'。有效链 `use_manual = formal is None or resolution != '采用正式'`；`effective_net = previous_effective_net + chosen_daily`——**手工与正式同一条累计链上拼接**，不两套账。

## 当前项目实现

### 预计持仓（futures_live_positions.py，576 行）

`build_estimated_positions`：官方月末持仓 + 逐条应用月末后手工成交（开仓加权均价/平仓扣量校验）+ 期权到期事件（`履约` 按 strike 建立标的期货仓）。铁矿石期权到期日 = **交割月前一月的第 12 个交易日**（`iron_ore_option_expiry_date`）。到期候选状态机：待到期 → 等待结算价 → 待确认（一次性确认全部手数）。行权方向链：买 put 行权→空期货、**空 put 被指派→多期货**、买 call→多、空 call→空。

### 正式价格（prices.py 250 行 + settlements.py 615 行）

- 收盘价：`INSERT OR IGNORE`（只填 NULL 行，`max_trade_date` 截断）；期权走 AkShare 期权日线（返回链即报错），期货走 TickFlow/AkShare；
- 结算价：**只在 NULL 时 UPDATE，永不覆盖**；冲突（>1e-8）保留原值并记 conflict；来源：CFFEX 月度 zip（`historysj/{YYYYMM}/zip`）、新浪期货日线 settle 列、大商所期权 dayQuotes（412 时明确说明"匿名旧接口已停用…未用收盘价冒充正式结算价"）、新浪期权链反推昨结算（`_infer_previous_settlement` 按 tick 网格吸附 ±3 档）；
- 需求表 `_historical_contract_requirements`：全部历史成交合约（含已平仓/到期）的首末日期，铁矿石期权扩展到 `min(到期日, 最新完成日)`。

### 盈亏视图（futures_live_pnl.py，473 行）

`build_current_position_pnl`：估值日 = `as_of`（晚于月末）或各活跃合约**价格共同日的最大值**；期权 `realized = 权利金现金流 − open_basis`（`open_basis = avg×qty×mult×(1 if 空 else −1)`）；若日账本可用且 ledger_date==估值日，**realized/floating/fee/net 全部以账本为准**。`summarize_futures_live_pnl`：官方费 = Σ月费 + 申报费；手工费 = 月末后未接管成交费；盯市口径不扣申报费（`include_declaration_fee` 参数在 settlement 模式下被忽略——设计使然）。

## 代码分析

**盯市与收盘的费用分离**（`_calculate_daily_account_state` 第 386-391 行注释）是全模块的口径锚点：settlement 扣"成交费+行权手续费"、close 扣"成交费+账户费+月度残差"。申报费是"撤单申报"的交易所费用，同花顺盯市不含它——为了与外部软件对得上，这里宁可让 close 口径多一个"残差挂账日"也要保持盯市纯净。

`_daily_fee_adjustments` 的残差挂账：`residual = monthly_fee − Σ明细费 − Σ账户级费用`，>0.05 元挂到该月最后一个交易日——**费用对齐日**是 close 口径月末"多出的一天亏损/盈利"的来源，读图时月末柱状异常先查这里。

`_apply_manual_daily_pnl_overrides` 是"读函数带写副作用"的典型：逐日核对结果直接 `executemany UPDATE` 回 overrides 表——一次构建同时完成对账落库，调用方（页面每次渲染调两次 close/settlement）隐式触发对账更新。

### 两个小模块的收尾

`futures_live_calendar.py`（15 行）用 **A 股日历**近似生成期货交易日序列（`weekday<5` 且非假日），是逐日账本的推进骨架与"缺失交易日"判定的依据——商品/金融期货与股票假日基本一致但非保证一致，这是全模块的一个隐式假设。`components/futures_live/history.py`（358 行）渲染账户趋势（口径 segmented_control 默认"盯市"、累计线+当日柱、稀疏刻度）、收益日历（复用 `core/return_calendar.py`，caption 原文声明"每日收益率以此前一交易日经济权益加当日正净入金为基数"）、合约历史盈亏、资金流水、成交明细（导出 CSV + 删除手工成交）与月度状态/导入记录（风险度 ×100 显示、逐条 warnings/error_message 解码）。

## 潜在错误

1. **新浪期权链反推只查"看跌合约"列**（settlements.py 248-253 行）——**call 期权（I2609C…）的当前持仓结算价永远取不到**，只能等历史接口；
2. 收盘口径断档次日无 daily_pnl（只重建基线）——柱状图出现空洞，用户可能误读为"零收益"；
3. 出金不减分母：大额出金后的日收益率分母维持原值——**收益率被系统性放大**（AGENTS.md 是有意如此，但解读时要知道）；
4. `build_current_position_pnl` 的 else 分支 `contract_closes` 赋值后立即被重新赋值——死代码；
5. 到期日扩展只支持铁矿石（其他品种期权无自动到期候选）；
6. `_fetch_cffex_settlement_history` 依赖中金所月度 zip 的可用性，接口变更时静默失败进 errors（有表面提示，无重试）。

## 改进方法

- 期权链反推补 call 列匹配（链表里看涨/看跌两个列族）；
- 断档日在 UI 用灰色柱 + "基线重建日"标注；
- `contract_pnl` 的缺失乘数成交计入 fee=0 但标"乘数缺失"警示列；
- 死代码清理；非铁矿石期权补到期日表（或按品种可配置的到期规则）。

## 实际案例

页面顶部的双口径对照（`components/futures_live/account.py` 的 `render_account_summary`）体现了这套会计的全部输出约定：15 个指标格中，**"全部盈亏（盯市）"与"累计净盈亏（收盘）"并排出现**，且只有当两个口径的 `valuation_date` 相同才显示盯市值（`mark_matches_close_date`），否则提示"需等待所有当前合约的同日结算价齐全"。收益日历 caption 原文："每日收益率以此前一交易日经济权益加当日正净入金为基数，周、月、年收益率按每日收益率复合"——把分母定义写在用户眼前。而 `futures_daily_pnl_overrides` 的对账三态（已一致/待核对/采用手工）配合 0.05 元容差，让"同花顺说赚 1200、系统算 1187.6"这类日常摩擦自动收敛为"已一致"，只有真正的分歧才升格为人裁——**这就是第 1 章"可解释优先于自动化"铁律在盈亏层的落地**。
