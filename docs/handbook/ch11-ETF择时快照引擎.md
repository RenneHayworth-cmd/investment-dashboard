# 第十一章 ETF 择时快照引擎：position_timing.py

## 理论

回测引擎回答"过去如何"，快照引擎回答"现在怎么办"。`services/position_timing.py`（590 行）是持仓页的信号核心，它把 MA 带状状态机包装成四个纯函数：单 ETF 快照、转变史、逐日仓位序列、近 7 日操作指引。它的设计约束与回测不同：

- **只读缓存**（formal history valid 才出信号）；
- **输出面向人**：`择时判断` 是"买入/卖出/持有/空仓/等待均线"这样的词，不是 0/1；
- **半仓 ETF 的措辞不同**：买入叫"加至满仓"、卖出叫"降至半仓"、空仓叫"半仓"——词面差异背后是仓位映射差异。

## 数学原理

快照状态机与第 9 章同构，输出新增四个时间序列量：

- `状态转换时间` $\tau$：最近一次仓位翻转日；
- `策略区间涨幅` $= P_{\text{now}}/P_\tau - 1$（从转换日收盘起算）；
- `上一状态转换时间` $\tau'$：转换事件序列的前一个；
- `策略上一区间涨幅` $= P_\tau/P_{\tau'} - 1$（已封口的完成收益）。

半仓映射 `etf_position_decision`（`position_timing.py:143` 起）：

$$\text{词} \mapsto \text{仓位}: \quad \text{买入}\to\text{加至满仓}(1.0),\ \text{卖出}\to\text{降至半仓}(0.5),\ \text{空仓}\to\text{半仓}(0.5),\ \text{持有}\to\text{持有},\ \text{等待均线}\to\text{半仓}$$

适用对象是 `ETF_POSITION_STRATEGIES` 中标"半仓持有半仓择时"的 159655/159501；其余 12 只纯择时原样透传。

## 代码分析

快照引擎在重构后是 `ma_timing_core` 的薄封装：`_clean_price_frame` 清洗 `date/price` 两列 → `_timing_states_and_ma` 调用 `ma_threshold_series + ma_threshold_states`（第 9 章的唯一状态机）得到逐日 0/1 仓位、均线与收盘价 → `_state_transition_rows` 从状态序列推导转换行（date/state/price/ma）。三态维持的语义完全由统一库承接：

```python
# ma_timing_core.ma_threshold_states（唯一状态机）
if np.isfinite(buy_line) and np.isfinite(close_values[index]):
    if close_values[index] > buy_line:   state = 1
    elif ... close < sell_line:          state = 0
# 带内或 MA 未形成 → 维持原状态（initial_state=0，空仓起步）
```

`initial_state=0` 与回测引擎冷启动语义完全一致——**历史数据不足时既不出假信号，也不把"数据不足"误报为"空仓卖出"**。

`_timing_action_position`（词→仓位，供停车聚合）把"降至半仓"映射为 0——字面上半仓还有 0.5 仓，为何映射为 0？因为停车聚合只用三只**纯择时**源（510500/159967/159552），半仓词根本不会出现在它们的信号里；这个映射是为防御性的全量兼容写的，注释与实现都自洽。

## 潜在错误

1. **承接行口径不一致（最重要）**：`build_recent_etf_operation_guidance` 的 512890 承接触发集用 `ETF_512890_TRANSFER_SOURCE_CODES`（**5 只全集**：588000、159915、510500、159967、159552），而停车快照与回测用 `ETF_512890_ACTIVE_TRANSFER_SOURCE_CODES`（**3 只活跃集**：510500、159967、159552）。后果：若 588000 卖出，操作指引会生成"承接588000空仓资金"的买入行，但正式的停车权重、50 万模拟绩效都**不会**承接——指引与绩效口径分裂。
2. 重算成本：信号状态机已统一进 `ma_timing_core`（numpy 循环），但每次实时预览仍对每只 ETF 全量重算 5000 行——正确但可缓存（状态序列只依赖缓存历史，历史不变即可复用）。
3. 转变记录用 `latest_action` 单变量滚动，若同一日内多次翻转（数据异常重复行）只留最后一次——`drop_duplicates("date")` 上游已保证不会发生，但这是隐式依赖。
4. `策略区间涨幅` 在转换日当天恒为 0（分母=分子），UI 上显示 0.00% 而非"-"，易被误读。

## 改进方法

- 统一承接触发集：让指引也用活跃集（或在 UI 显式区分"活跃承接/预留承接"两行）——这是一行配置的修改，收益是消灭指引与绩效的口径分裂；
- ~~快照函数向量化~~——信号部分已随 `ma_timing_core` 统一（numpy 循环）；剩余优化是历史不变时缓存状态序列；
- 转换日当天的区间涨幅显示为"-"或"转换当日"，避免 0.00% 歧义；
- 参数表增加"冻结版本号"字段，与 `frozen_strategy_20260728.json` 的 `parameter_version` 联动校验。

## 实际案例

2026-09-03 上午用正式缓存（截至 9-02）重放停车快照与 50 万策略（完整数字见 `output/handbook_backtest_results.json`）：512890 组合权重 **20%**（两只源空仓）、`择时判断=持有`、状态转换 **2026-08-24**、区间涨幅 +1.01%、上一转换 2026-08-14、上一区间 **+2.94%**。对照 50 万策略的成交记录，8-24 当天恰好发生两笔"卖出源 + 买入 512890"（510500 卖出 6300 份 @7.74，同日买入 512890 41600 份 @1.189；159967 同模式）——**快照的 8-24 转换与回测的 8-24 承接完全对齐**，这是"展示信号与回测引擎同源"的最直接证据。而当周实际累计收益 -0.80%（净值 0.9920）也说明：择时组合不是每天赚钱的机器，8 月最后一周它把 513310、159967、510500 陆续切到了停车仓。
