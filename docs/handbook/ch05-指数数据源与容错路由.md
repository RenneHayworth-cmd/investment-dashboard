# 第五章 指数数据源与容错路由：index_config + index_sources_*

## 理论

免费行情源的可靠性不服从正态分布而服从"长尾故障"：单点接口随时可能限频、改版、返回半截数据。工程上唯一稳健的做法是**路由 + 多级回退 + 已结算过滤**：把"用哪个源"变成配置（`INDEX_CONFIG` 每个指数声明 `source`），把"源挂了怎么办"变成显式 attempts 链，把"数据能不能信"变成时间过滤（`filter_completed_market_dates`）。

## 数学原理

数据源的可用性建模：设源 $i$ 单次请求成功率为 $p_i$，一条 attempts 链 $(1,\dots,k)$（各源独立）的整体成功率是

$$P_{\text{chain}} = 1 - \prod_{i=1}^{k}(1-p_i)$$

A 股指数链是 3 级（`index_zh_a_hist` → `stock_zh_index_daily_em` → `stock_zh_index_daily`），即使每级 $p=0.7$，链条成功率 $1-0.3^3=97.3\%$。这就是"多级回退"的数学意义：**可靠性是乘法补集，不是平均**。此外 Yahoo 并发闸门 `YAHOO_REQUEST_GATE = BoundedSemaphore(2)` 把并发请求速率压到避免 429 的水平——成功率的另一面是"别把自己限死"。

### 六个源模块（services/index_sources_*.py）

- **akshare（423 行）**：`get_index_data_from_akshare_cn` 的 attempts 链为 `ak.index_zh_a_hist` → `ak.stock_zh_index_daily_em(f"{market}{code}".lower())` → `ak.stock_zh_index_daily`；`akshare_us` 主源 `ak.index_us_stock_sina`、Yahoo 只并"更新日期"的行；`akshare_global` 对稀疏历史（<20 行或日期间隔中位数 >7 天）整表换 Yahoo；`get_index_data_from_cboe_vix` 直连 `cdn.cboe.com` 的 `VIX_History.csv`（timeout=10，`trust_env (False,True)` 两轮）。
- **eastmoney（599 行）**：kline 端点 `klt=101, lmt=max(days*3,120)`，4 个 host 轮试；报价端点 `stock/get`（timeout=3，`f43`=最新价、`f60`=昨收、`f170`=涨跌幅）；港股三路独立补充 `_supplement_hk_independent_rows`：新浪日线 → 妙想日线 → 恒生官网单行，`merge_newer_index_rows` 只并更新日期。
- **sina（170 行）**：`fetch_hsi_official_completed_close` 从恒生官网 `performance.do` 取"今天已更新且 ≥ 收盘时刻 → indexValue；lastUpdate 晚于目标日且目标日是其前一交易日 → previousClose"，宁缺毋滥；`fetch_sina_hk_realtime_quote` 供 HSHYLV 实时卡。
- **mx（185 行）**：东方财富"妙想"大模型接口，`MX_HISTORY_MAX_BARS=500`，**只接受 `code == expected_code`（`HSHYLV.HI`）**的返回实体——AGENTS.md 明确禁止用 `861520.EI` 给 `90.BK1158` 兜底（两者绝对水平与日收益都不同）。
- **tickflow（99 行）**：`count=max(days*2, 80)`；只有带 api_key 才补实时行（免费通道不补）。
- **yahoo（164 行）**：`trust_env (True, False)` 与其他源相反（两个 host 都 401/403 时换代理无意义，直接 break）；错误信息只留最后 2 条防日志爆炸。

### 聚合门面（index_sources.py，13 行）

`from services.index_sources import *` 把 yahoo/eastmoney/akshare/tickflow 四个模块的公开符号聚到单一命名空间，供旧代码使用；`index_sources_sina` 与 `index_sources_mx` 未聚合（它们只被 eastmoney/realtime 内部使用）。四个模块函数名互不重叠，星号导入无覆盖风险。

### 路由器（index_source_router.py，91 行）

`fetch_index_from_source(index_name, index_config, days=30)` 按 `source` 分派到 10 种处理器，未知 source 抛 `ValueError`。它不做网络与缓存，是纯路由。

## 代码分析

值得精读的三个容错细节：

1. **东财报价行的三态合并**（`append_eastmoney_quote_row`）：quote 日 < 最新历史日 → 忽略（防回退）；== 且 `replace_same_day=True` → 原位覆盖当日 close；> → append。这保证报价行永远不会"倒插"历史。
2. **已结算单行获取**（`fetch_eastmoney_completed_global_row`）：quote 时间（UTC→市场时区）必须等于 `latest_settled_trade_date` 且 **≥ 当日最后时段结束时刻 − 1 分钟**才返回，否则 None。全球指数的"今日价"只有确认收盘后才存在。
3. **Yahoo 时间戳陷阱**：`datetime.fromtimestamp(timestamp)` 不带 `tz` 参数，用运行机器本地时区解释 epoch。对中国时区部署，美东日线时间戳（北京时间 21:30/22:30）日期正确；换到 UTC+13 部署就会跨日错位——同文件其他地方都写了 `fromtimestamp(tz=...)`，唯独两处漏了（第 89、148 行附近）。

## 潜在错误

1. `append_akshare_latest_index_row` 的 Yahoo 兜底硬编码 `.SS` 后缀——深市指数（399006）语义错误，仅因 Yahoo 查不到才未暴露；
2. `append_futures_spot_row` 非 CFFEX 分支不校验时间，夜盘品种（AU/AG/SC）21:00 后抓到的价会以当天日期 append 为"当日 close"（夜盘归属次日与否取决于品种规则，此处未区分）；
3. `append_hk_index_spot_row` 价格列回退 `spot_df.columns[2]` 依赖新浪列顺序，脆弱；
4. 妙想 `_number` 用正则提取第一个数字，"约 3,000 点"也能解析出 3000——宽松解析在实体校验严格（仅 HSHYLV.HI）的前提下可接受，但扩展到其他实体时是隐患；
5. csindex 对 H30269 的特判里 `raise` 会终止当前 attempt，已 append 的东财报价行被丢弃重拉（重复网络请求）。

## 改进方法

- 把 Yahoo `.SS` 硬编码改为按 `market` 参数推断 `.SS/.SZ`；
- 给期货 spot 补充按品种的会话校验（复用 `FUTURES_TRADING_SESSIONS`）；
- 统一 `fromtimestamp(t, tz=ZoneInfo(...))` 并加一个 lint 规则禁止无 tz 的 fromtimestamp；
- attempts 链的结果统一记入 `timings`（现有 `build_timing_row` 已支持），把"用了哪一级回退"在 UI 透出，方便发现主源劣化。

## 实际案例

以"恒生港股通高息低波"（HSHYLV）为例看三重独立源如何协作（这是全系统数据源最复杂的标的）：

- **正式日线主链**：东财 kline（`124.HSHYLV`）→ 缺目标日时 `_supplement_hk_independent_rows`：新浪 `stock_hk_index_daily_sina`（双重 `filter_completed_market_dates`）→ 妙想日线（限 500 bar，仅收 `HSHYLV.HI`，只留已收盘日）→ 恒生官网单行（`hshylv` 系列）。
- **实时卡**：先新浪 `rt_hkHSHYLV`（timeout=5，≥19 字段校验），失败再妙想实时（要求报价时间 == 当天）。
- **更新复核**：`verify_updated_index_data` 对它用恒生官网收盘做独立源，容差 ±0.20%。

本地缓存证实这条链的真实产出：`index_final_history/index_raw_恒生港股通高息低波_1d.csv` 截至 2026-08-14 有 1 行——说明其余日期由长历史与新浪路径在别的缓存层提供，而该层的单行正是"宁缺毋滥"策略的体现：拿不到已确认的已结算行，就只写拿得到的那一行。
