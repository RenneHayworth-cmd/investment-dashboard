# 第二十八章 缺陷清单、改进路线图与研究议程

> 前二十七章在"潜在错误"小节里零散标记了问题。本章把它们集中成一个带优先级的缺陷清单（P0=影响正确性，P1=影响可用性/一致性，P2=工程质量），并给出可执行的改进路线与研究议程。这是全书唯一以"缺陷"为主语的章节——因为诚实的系统文档必须包含"哪里会错"。

## 理论

软件缺陷在量化系统里的分类与普通软件不同：**正确性缺陷**（算错账、错信号）会直接变成钱上的错误决策；**口径缺陷**（两处定义不一致）最隐蔽——每一处单独看都对，合起来自相矛盾；**流程缺陷**（硬编码、无校验）在配置变化时爆发。本章按此三类组织，"潜在错误"一节即缺陷清单本体。

## 数学原理

口径一致性可以形式化为"同构判定"：设两处实现为函数 $f, g$，若存在输入域 $X$ 使 $\exists x: f(x) \ne g(x)$ 且语义上应相同，则口径分裂。本手册发现的主要分裂点（承接口径 5 只 vs 3 只、当日收益分母双口径、等号归属、夏普无风险利率两版）都可以用**共享纯函数库**消除——把状态机、分母公式各写一次，调用方只做包装。这比写对账测试更根本：**不存在两个实现，就没有不一致**。

## 代码分析

### 修复优先级的一个判据

P0-3（承接口径）值得单独分析，因为它是**三类缺陷的交集**：`ETF_512890_TRANSFER_SOURCE_CODES` 与 `ETF_512890_ACTIVE_TRANSFER_SOURCE_CODES` 两个常量并存（口径分裂的根因）、`build_recent_etf_operation_guidance` 选错了常量（正确性缺陷的表现层）、而回测侧 `_build_allocations` 用活跃集是对的（所以绩效与指引打架）。修复只需一行（指引改用活跃集），但**必须同时**检查 `ETF_PORTFOLIO_WEIGHTS_PCT` 里 588000/159915 权重为 0 的事实——它们当前不进组合，所以 5 只全集在本配置下不会实际触发差异；一旦未来给 588000 配了权重，bug 立即从潜伏转为显性。**修复前先写一个"588000 卖出"的回归测试**，把潜伏态钉死。

## 实际案例

### 一轮"缺陷→修复→验证"的完整想象

以 P1-6（当日收益双口径）为例走一遍修复流程，示范本手册的工程方法：

1. **钉死现状**：写测试 A 断言正式层分母 = `prior_market_value + 当日买入成本`（`position_performance._build_current_positions`）；写测试 B 断言叠加层分母 = `昨收×数量`（`components/position/performance._overlay_strategy_positions_with_realtime`）——两个测试同时通过，证明分裂存在；
2. **定标**：AGENTS.md 明文要求正式口径含买入成本 → 叠加层向正式层看齐；
3. **改**：叠加层分母改为 `昨收×数量 + 当日买入成本`（需要把 trades 传入叠加层或预计算当日买入成本映射）；
4. **回归**：测试 B 改断言新公式；用手册的重放脚本对比修复前后 2026-08-05→09-02 的每日收益率序列，唯一差异日应为"有当日买入的日期"（8-05 建仓日、8-14/8-18 买入日）；
5. **文档**：AGENTS.md 增补一句口径声明，本手册修订第 21 章。

这个流程的要点：**先用测试钉住分裂，再用文档定标，改完用真实数据回归**——三步缺一不可，否则"修好一个 bug，引入两个口径"。
