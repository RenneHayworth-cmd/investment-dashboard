## 3. 统一框架重构说明

### 3.1 `services/ma_timing_core.py`

- `ma_threshold_states(close, ma_period, threshold_pct)`：唯一的"纯信号"状态机（初始空仓，MA 不足保持，带内维持）。
- `threshold_desired_position(...)`：账户自愈语义（带内锚定实际持仓），单标的回测使用。
- `simulate_timing_account(close, states, config)`：参考账户模拟器，显式支持 `after_close / next_open / next_close` 三种执行口径 + 滑点 + 单边费率 + 整手 + 停牌处理。
- 等价性验证：`tests/test_ma_timing_core.py` 断言模拟器 after_close 零滑点输出与既有 `run_ma20_timing_backtest` 的净值、交易笔数、逐笔已实现盈亏完全一致（多路径随机价格）。

### 3.2 `core/metrics.py`

`annualized_return / sharpe_ratio / annual_volatility / drawdown_series / max_drawdown / longest_underwater_days / calmar_ratio / trade_win_stats / seeded_returns` 唯一定义；`fund_rotation_metrics / fund_rotation_summary / fund_rotation_timing / annual_etf_selection / portfolio_audit_metrics / dynamic_threshold_research / ma_timing_core` 全部委托。行为修正仅两处（E1 极端亏损年化、E2 波动率下限），其余口径保持逐位一致（由既有 442 项单元测试锁定）。

### 3.3 研究管线（`scripts/research/`）

- `grid_engine.py`：向量化参数网格引擎（MA5..120 × 阈值 0..4%），`validate_grid_engine.py` 与事件模拟器交叉验证：cost=0 逐日收益差 < 1e-10（仓位路径完全一致）；6bp 费率下 NAV 相对差 < 5e-4（加法 vs 乘法费用的已知交叉项，量级 ret×cost）。
- `run_strategy_validation.py`：全量回测 + 样本内/外 + 滚动 + 邻域敏感性 + 全网格 + Bootstrap + 漏单蒙特卡洛 + 成本压力 + 牛熊分段 + 相关性 + 组合回测，输出 `output/research_audit/` 与 `run_manifest.json`（输入 sha256 + 全部参数）。
